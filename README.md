# Offensive Security Portfolio

##  About This Repository
Welcome. This repository serves as a living documentation of my journey in offensive security and red teaming.

The purpose of this portfolio is to demonstrate my technical methodology, from initial enumeration to exploitation and remediation. It showcases my ability to not only execute technical attacks but to document them in a way that is useful to clients. 

##  Repository Structure
All files are PDF-files that are eaither the resulting documentation from boxes on platforms like Hackthebox or Tryhackme. There are also some written content on topics that I find interesting.

##  Methodology
My approach applies a systems engineering mindset to security. While I expect my methodology to improve and develop over time, attempting to both see both the details and how those details relate to the big picture. I focus on understanding the underlying logic of the target to identify design flaws and architectural vulnerabilities. 

## Decleration of AI Use
While AI may be useful in many cases, I believe that there are more cases where AI should not used. My main use for it professionally is to check understanding. I also use AI for feedback and I typically use "reasoning models" for this. I generally do not use AI to produce text as I think it is incredibly uninteresting to both "create" and read AI output. It is my firm belief that we should not outsource the thinking part of the brain to AI as we will likely become incredibly lazy and unable to do things without it. 

When using AI, I generally use API with TypingMind as the frontend. This let's me try new (and old) models for different tasks without me having to rely on a subscripton.
